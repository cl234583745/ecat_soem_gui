# ECAT Bench 需求说明

版本：0.1  
目标平台：Windows 10/11 x64，后续支持 Linux/macOS  
产品定位：用于 EtherCAT 主站/从站联调、故障定位和固件维护的轻量桌面工具

## 1. 产品目标

提供一个打开即用的 EtherCAT 主站调试台。用户应能在几分钟内选择网卡、扫描从站、检查拓扑、切换状态机、读写 SDO、查看或修改 PDO、发送邮箱请求并完成 FoE 固件升级。

产品不替代 TwinCAT 3、CODESYS 或完整 PLC 工程系统。它不承担运动控制编程、PLC 任务编排、完整 ESI 设备库管理和产线配方管理。它是一款高信息密度、低启动成本、可诊断、可脚本化的现场工具。

## 2. 核心用户与场景

### 2.1 设备开发工程师

- 连接新开发的 EtherCAT 从站，确认 EEPROM 身份、AL Status、PDO 长度和状态迁移。
- 通过 SDO 修改参数，再观察输入 PDO 变化。
- 通过 FoE 下载新固件并重新扫描验证版本。

### 2.2 现场调试工程师

- 快速判断断链位置、从站丢失、WKC 异常或周期抖动。
- 将总线从 PRE-OP 推进到 SAFE-OP/OP。
- 导出诊断快照，发给研发复现问题。

### 2.3 测试/自动化工程师

- 用固定 JSON 命令驱动核心，执行可重复的 SDO、状态机和 FoE 测试。
- 采集周期时间、抖动、丢帧、WKC 和 AL Status。
- 将诊断记录纳入 CI 或硬件在环测试。

## 3. 功能需求

### 3.1 网卡与实时参数

- `FR-NET-001` 列出可用的物理以太网适配器，显示名称、MAC、链路状态、驱动和是否适合专用 EtherCAT。
- `FR-NET-002` 要求总线运行时锁定网卡；切换网卡必须先停止总线。
- `FR-NET-003` 支持选择原始报文驱动，例如 Windows Npcap/NPF。
- `FR-NET-004` 周期可配置范围为 250 µs 至 10 ms，默认 1 ms。
- `FR-NET-005` 分别配置发送超时、接收超时、实时优先级、CPU 绑核与 Distributed Clock。
- `FR-NET-006` 支持扫描后自动进入 OP，但默认应显示明确的安全提示。
- `FR-NET-007` 配置在桌面模式持久化到用户数据目录。

### 3.2 总线扫描与拓扑

- `FR-SCAN-001` 启动主站后执行 EtherCAT 扫描，识别从站数量、顺序和地址。
- `FR-SCAN-002` 显示位置、名称、Vendor ID、Product Code、Revision、Serial、AL Status、WKC 和 DC 状态。
- `FR-SCAN-003` 检测并显示断链、从站数量变化、身份变化和状态异常。
- `FR-SCAN-004` 扫描结果可导出为诊断快照。
- `FR-SCAN-005` 后续导入 ENI 时，应比对实际拓扑和期望拓扑。

### 3.3 状态机

- `FR-SM-001` 支持 INIT、PRE-OP、SAFE-OP、OP 状态显示。
- `FR-SM-002` 支持单从站和整组从站状态切换。
- `FR-SM-003` 只允许符合 EtherCAT 顺序的状态迁移；每次迁移等待 AL Status 超时确认。
- `FR-SM-004` OP 操作前显示输出可能立即生效的警告。
- `FR-SM-005` 保存最近迁移原因、目标状态、耗时和错误码。

### 3.4 PDO 过程数据

- `FR-PDO-001` 显示每个从站的输入/输出 PDO 对象、索引、子索引、类型、单位和当前值。
- `FR-PDO-002` 输入 PDO 以不低于 10 Hz 的界面刷新率显示，不能阻塞实时循环。
- `FR-PDO-003` 输出 PDO 可编辑并写入周期映像，必须显示写入确认。
- `FR-PDO-004` 支持停止周期、重新启动周期和观察 WKC。
- `FR-PDO-005` 正式版本必须支持 ENI 固定 PDO 映射，不能只依赖 SOEM 自动映射。
- `FR-PDO-006` 支持十六进制、十进制和按类型格式化显示。

### 3.5 SDO / CoE

- `FR-SDO-001` 支持指定从站、对象索引、子索引、数据类型、Complete Access、上传和下载。
- `FR-SDO-002` 显示耗时、十六进制响应、十进制响应和错误信息。
- `FR-SDO-003` 保存当前会话访问历史。
- `FR-SDO-004` 支持对象字典快捷入口；后续可从 ESI/ENI 动态生成对象列表。
- `FR-SDO-005` SDO 操作必须验证十六进制输入、索引范围和从站能力。

### 3.6 邮箱诊断

- `FR-MBX-001` 支持 CoE、EoE、FoE、AoE 原始邮箱请求入口。
- `FR-MBX-002` 显示 TX/RX payload、事务耗时和错误。
- `FR-MBX-003` 邮箱任务必须与周期线程隔离，不允许 GUI 直接调用 SOEM。
- `FR-MBX-004` 后续提供 EoE IP 配置、邮箱重试与超时策略。

### 3.7 FoE 固件

- `FR-FOE-001` 支持从主站下载固件到从站，也支持从从站上传固件。
- `FR-FOE-002` 支持文件选择、文件大小显示、可选密码和任务进度。
- `FR-FOE-003` 显示运行、完成、失败、取消状态，完成后执行 CRC 或从站确认。
- `FR-FOE-004` 任务执行期间阻止重复 FoE 任务。
- `FR-FOE-005` 中断后提示设备可能停留在 Bootloader，并支持重新扫描。

### 3.8 配置与诊断

- `FR-DIAG-001` 显示周期时间、抖动、WKC、丢帧、DC offset、邮箱错误和运行时长。
- `FR-DIAG-002` 显示最多 240 条当前会话日志，并支持导出 JSON 诊断包。
- `FR-DIAG-003` 支持加载和显示 ENI 绑定状态。
- `FR-DIAG-004` 支持导出配置、拓扑、计数器和事件。

## 4. 非功能需求

### 4.1 实时性

- `NFR-RT-001` 1 ms 周期是默认目标，支持 250 µs 至 10 ms 配置。
- `NFR-RT-002` GUI 渲染、日志落盘、IPC 编码和文件操作不得在周期线程执行。
- `NFR-RT-003` 周期线程不得进行动态内存分配、阻塞 I/O、异常驱动的常规流程或每周期日志格式化。
- `NFR-RT-004` 1 ms 是 Windows 软实时目标。验收必须记录周期直方图、p99、p99.9、超时、丢帧和 WKC，不得宣称硬实时。
- `NFR-RT-005` 邮箱任务应由核心调度器串行执行，原则上不得让 PDO 周期长期停顿。

建议验收条件（需在指定测试机、专用网卡和固定拓扑上执行）：

- 1000 µs 设定下连续运行至少 30 分钟。
- p99 周期时间不超过 1050 µs。
- p99.9 周期时间不超过 1200 µs。
- 无持续 WKC 错误。
- 测试报告中同时记录 CPU、OS、网卡、从站数量和背景负载。

### 4.2 稳定性与故障隔离

- `NFR-REL-001` GUI 崩溃不得导致已启动的真实主站核心无人监管；主进程必须检测核心退出并停止总线。
- `NFR-REL-002` 核心异常必须记录结构化错误，并在重连后重新扫描，不能盲目恢复 OP。
- `NFR-REL-003` 网络断开、从站掉线和 WKC 异常必须有清晰提示。
- `NFR-REL-004` 用户配置损坏时回退到安全默认值。

### 4.3 性能

- `NFR-PERF-001` 桌面首屏在普通办公笔记本冷启动目标小于 3 秒。
- `NFR-PERF-002` 运行遥测界面刷新限制在 10-20 Hz，不随周期频率刷新。
- `NFR-PERF-003` 扫描 128 个从站时界面仍保持可操作，扫描进度可见。

### 4.4 安全

- `NFR-SAFE-001` OP 切换与 PDO 输出写入必须有明确动作确认或危险色提示。
- `NFR-SAFE-002` FoE 中断、SDO 写入和固件升级必须记录目标从站。
- `NFR-SAFE-003` Electron 启用 `contextIsolation`、关闭 `nodeIntegration`、限制导航和新窗口。

### 4.5 可移植性

- `NFR-PORT-001` GUI 使用 Web 标准与 Electron，Windows 优先。
- `NFR-PORT-002` 核心使用 C++20 和 SOEM，Linux 使用 libpcap，macOS 需评估权限和 BPF。
- `NFR-PORT-003` 平台差异集中在核心与适配器发现层，UI 不包含平台特定代码。

## 5. 数据对象

核心状态至少包含：

- 主站阶段、连接态、扫描态、网卡 ID。
- 从站身份、AL Status、状态、WKC、DC、输入/输出 PDO。
- 周期、抖动、WKC、丢帧、DC offset 与历史采样。
- 运行事件与邮箱错误。
- FoE 任务方向、文件、进度、状态。
- 主站配置与能力声明。

## 6. 阶段交付

### Phase 0：可演示 MVP

- 完整 GUI 与模拟核心。
- 原生 JSON-IPC 模拟核心。
- 单元测试、UI 冒烟测试、原生核心冒烟测试。

### Phase 1：硬件可用

- 固定 SOEM v2 与 Npcap 构建。
- 真实网卡枚举和独占。
- 真实扫描、状态机、SDO、PDO 观察。
- 1 ms 基准测试工具与报告。
- OP 下 cyclic mailbox 路径和下载进度。

### Phase 2：现场工具

- ENI 解析与固定 PDO 映射。
- 邮箱调度在真实拓扑和高负载下的验收、重试与超时策略。
- FoE 上传确定进度、传输中取消、恢复和主站侧 CRC。
- ESI 对象字典导入。
- 原始帧抓包和增强诊断。

### Phase 3：跨平台与自动化

- Linux/macOS 核心。
- CLI 与 JSON 脚本接口。
- 硬件在环测试。
- 安装包签名和自动更新。

## 7. 明确不在 MVP 范围

- PLC 编程、运动控制轨迹规划和完整工程生命周期。
- 分布式时钟全拓扑高精度同步认证。
- 完整 ESI/ENI 编辑器。
- 主站冗余、热连接和线缆冗余。
- 安全 SIL/PL 认证。
